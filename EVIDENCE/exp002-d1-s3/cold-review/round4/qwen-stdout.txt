### 1. `delta_reaudit.sh` arms a destructive `EXIT` trap *before* its dirty-tree refusal, so the refusal path can discard uncommitted work

- **Severity:** medium
- **Where:** `EVIDENCE/exp002-d1-s3/delta_reaudit.sh:24`
- **Quote:**
  ```
  trap 'git restore -- "$MOD" 2>/dev/null' EXIT
  ```
  (with `:19` `MOD=python/prin/reporting/figure_generation.py`, `:34` `[ "$(git status --porcelain --untracked-files=no | wc -l)" -eq 0 ] || { echo "tree is not clean; refusing to run"; exit 2; }`, and the first *intended* destructive restore at `:52`)
- **Claim:** The trap is installed ten lines before the clean-tree guard, so when the script prints "tree is not clean; refusing to run" and exits 2, the `EXIT` trap still fires and runs `git restore -- python/prin/reporting/figure_generation.py` — irrecoverably discarding any *unstaged* edits to exactly the module under correction, in the one situation where the script has decided it must not touch the tree. `2>/dev/null` hides it. (Blast radius is one file: the guard trips on any tracked modification anywhere, but the restore only bites when that file itself is dirty — which is precisely the case a developer re-running the re-audit mid-edit would be in.) The two sibling gate scripts get this right: `closing_gate.sh:28` and `final_legs.sh:21` both check the clean tree *before* any `rm -rf` and install no trap.
- **Reproduce:**
  ```
  rg -n "^trap |refusing to run|^git restore --source" EVIDENCE/exp002-d1-s3/delta_reaudit.sh
  bash -c 'f(){ trap "echo TRAP-FIRED-ON-REFUSAL-PATH" EXIT; echo "refusing to run"; exit 2; }; f'
  ```
  (The second command is read-only; it shows bash runs the `EXIT` trap on the `exit 2` refusal path. Fix: arm the trap only after `:52` has actually run, e.g. a `RESTORED=0/1` flag tested inside the trap.)

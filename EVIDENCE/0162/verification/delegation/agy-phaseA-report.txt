## 2. In-Depth Verification of In-Scope Areas

### 2.1 Decision Rules (§4.1)
- **Counterexample Priority over Coverage:** Verified in [`_verdict`](file:///C:/dev/PRIN/DOCS/experiments/EXP-002-api-benchmark-result-and-reproduction-parity/analysis/exp002_e4_analysis.py#L1870-L1875):
  ```python
  if counterexamples:
      return REFUTED
  return CONFIRMED if complete else INCONCLUSIVE
  ```
  For all hypotheses (H1–H4), counterexamples are counted and evaluated first. Any positive counterexample count immediately short-circuits to `REFUTED`, regardless of completeness or missing coverage.
- **Incomplete Coverage Safeguard:** No hypothesis can return `CONFIRMED` with incomplete coverage:
  - **H1:** Requires `not unverifiable` and that all 175 expected symbols resolve without missing names.
  - **H2:** Requires `complete = len(record.cases) == 62 and all(block["missing_claim_comparator_records"] == 0 for block in families.values())`.
  - **H3:** Requires `complete = equal_registered == 39 and archived_equal == 11`.
  - **H4:** Requires `complete = registered <= set(first) and set(first) == set(second)`.
- **Inadmissible Record Handling:** Any inadmissible record (aborted, tampered, schema violation, or unverified origin) sets `record.census`, `record.cases`, or `record.arm` to `None`. In all adjudication functions, a missing arm/census returns `INCONCLUSIVE` (with diagnostic reasons preserved in `summary.json` and Markdown tables); an inadmissible record never returns `REFUTED` or `CONFIRMED`.
- **Zero Trust in Driver Status / Booleans:** The analysis does not consume driver success Booleans as verdicts:
  - H1 re-derives row classification from retained `type`, `callable`, and `error` attributes and validates legacy ownership against git blobs at commit $R$.
  - H2 re-evaluates all 62 predicates from the manifest-verified frozen JSON inputs, comparing operands directly.
  - H3 and H4 re-compare hashes and sizes directly across arms and against the 11 archived tables.

- **Approved vs. Sensitivity Policies:**
  - **Approved policy:** Tables canonicalized CRLF $\to$ LF; PDFs evaluated with registered Info metadata keys stripped and xref offsets canonicalized to 0; PNGs normalized.

  - Divergence between the frozen reference generator and archived tables is tracked and reported separately (`reference_tables_inconsistent_with_archived`).
  - Renderer/font environment differences between compared arms return `INCONCLUSIVE` per §4.2 item 3.

### 2.11 Security & System Integrity
- **Command Injection:** All git queries use list-based argument arrays without shell invocation (`shell=False`). Subprocess input is directed to `DEVNULL`. Git arguments are restricted to fixed constants and 40-character hexadecimal SHAs validated by `_HEX40.fullmatch`.
- **Path Traversal:** File paths in manifests and observation records are sanitized: absolute paths, parent directory traversals (`..`), and backward slashes (`\`) are rejected.
- **Link & Junction Rejection:** Windows directory junctions and symlinks across all path ancestors are detected via `stat.S_ISLNK` and `FILE_ATTRIBUTE_REPARSE_POINT` (0x400) and rejected.
- **TOCTOU Protection:** File descriptors are opened with `O_NOFOLLOW` / `O_BINARY` and verified against pre-open `lstat` attributes (`st_dev`, `st_ino`) prior to reading.

#### A. Windows Toplevel Comparison
- **Implementation:** [`tools/wp001_baseline.py:1038-1048`](file:///C:/dev/PRIN/tools/wp001_baseline.py#L1038-L1048):
  ```python
  1038:         toplevel = subprocess.run(  # noqa: S603  # nosec B603
  1039:             [executable, "-C", str(root), "rev-parse", "--show-toplevel"],
  1040:             capture_output=True,
  1041:             check=True,
  1042:             text=True,
  1043:             timeout=60,
  1044:         ).stdout.strip()
  1045:         # Only a work-tree root is inventoried through git; a directory nested
  1046:         # in some other repository (e.g. a test's tmp_path) is walked instead.
  1047:         if Path(toplevel).resolve() != root.resolve():
  1048:             return None
  ```
- **Forward vs back slashes:** `git rev-parse --show-toplevel` on Windows produces POSIX-style paths (e.g. `C:/dev/PRIN`). Passing this into `Path(toplevel).resolve()` normalizes all separators to Windows native backslashes (`C:\dev\PRIN`).
- **Drive-letter case & 8.3 short names:** In Python on Windows, `Path.resolve()` invokes `os.path.realpath`, which queries `GetFinalPathNameByHandleW`. This canonicalizes drive letters to uppercase (e.g. `C:\...`) and resolves short 8.3 names (e.g. `PROGRA~1`) to long path names on both `toplevel` and `root`.
- **Symlinked roots:** `Path.resolve()` resolves filesystem symlinks/junctions on both sides to the target directory.
- **Nested directories:** When `root` is a subdirectory within a git work-tree (such as a test's `tmp_path` under `.pytest_basetemp`), `Path(toplevel).resolve() != root.resolve()` evaluates to `True`, correctly returning `None` and falling back to `os.walk(root)` ([`tools/wp001_baseline.py:1047-1048`](file:///C:/dev/PRIN/tools/wp001_baseline.py#L1047-L1048)).

#### B. Deleted-but-Tracked Files
- **Implementation:** [`tools/wp001_baseline.py:1083`](file:///C:/dev/PRIN/tools/wp001_baseline.py#L1083):
  ```python
  1083:                 or not path.is_file()
  ```
- `git ls-files --cached` outputs all files present in the Git index, including files unlinked from the filesystem without staging.
- Line 1083 checks `not path.is_file()`. If a tracked file has been deleted from disk in the working copy, `path.is_file()` returns `False` and the file is omitted. This prevents nonexistent paths from entering the inventory and avoids `FileNotFoundError` during subsequent stat/line counts.

#### C. Submodules and Nested Repositories
- Git submodules are registered as gitlink entries in the index. `git ls-files` without `--recurse-submodules` prints only the submodule root directory path.
- On disk, `(root / name)` is a directory, not a regular file; `path.is_file()` ([`tools/wp001_baseline.py:1083`](file:///C:/dev/PRIN/tools/wp001_baseline.py#L1083)) evaluates to `False`, skipping it. Submodule contents are not traversed. (PRIN has no submodules; all workspace members are monorepo directories).
- Untracked nested repositories are directories and are likewise skipped by `not path.is_file()`.

#### D. Non-UTF-8 Filenames and `core.quotepath`

- **Encoding & Fallback:** [`tools/wp001_baseline.py:1064-1066`](file:///C:/dev/PRIN/tools/wp001_baseline.py#L1064-L1066):

  If any filename contains un-decodable bytes, `listing.decode("utf-8")` raises `UnicodeDecodeError`. This is explicitly caught at line 1065, returning `None` and safely falling back to `os.walk(root)`.

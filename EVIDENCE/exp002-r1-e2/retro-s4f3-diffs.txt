    fix(tests): measure daemon overhead in process CPU time, not wall time (DV-032)
    
    Closes EXP002D1-S4-F3 and implements the fix path DV-032 has carried since
    2026-09-01: "convert each to a seeded frame-count / pytest-benchmark case with
    an explicit tolerance".
    
    test_no_gpu_throughput_regression asserted
    median(with_daemon)/median(baseline) < 1.30 over WALL-CLOCK timings. Two measured
    facts made that unusable in a required gate:
    
      * It carried no signal. The daemon blocks on _state_queue.get and the test
        submits only three states, so exactly 3 inferences (~1.5 ms each) run inside
        a ~420 ms window: a maximum expressible effect of ~1.1% against a 30%
        allowance, ~27x below tolerance.
      * So it measured only host noise. At 814b670c it returned 22.07 in-suite and
        2.13 / 3.42 in isolation at 97-99.7% host CPU, while passing 5/5 on a quiet
        host. It turned a required gate leg red on a commit whose diff did not touch
        it, and DV-032 documents its expected band as "~1.28-1.32 under load".
    
    Overhead is now measured with time.process_time(), which excludes time spent
    waiting for other processes and so cannot be inflated by unrelated host load.
    Samples grew from n=1_000_000 (~60 ms) to n=8_000_000 (~480 ms) because the
    Windows process-time tick (~15.6 ms) made a 60 ms sample quantise to ratios of
    0.8000 / 0.8750 / 1.1429 -- one tick moved the ratio ~25%. At ~480 ms a tick
    moves it ~3%.
    
    Three deterministic assertions now carry the real signal and are load-invariant:
    error_count == 0, dlq_size == 0, inference_count >= submitted. The drain waits
    on every submitted state being HANDLED (inference_count + error_count), not on
    the queue reading empty -- the queue is empty once the daemon dequeues an item,
    before it finishes inferring it, so an emptiness-based drain observes the count
    mid-flight and fails spuriously.
    
    Measured ratio, normal daemon: 1.03 quiet, 1.02 under a host saturated with one
    busy process per logical CPU. The old metric under the same saturation produced
    22.07 / 2.13 / 3.42. The bound is 1.60, sized from a worst observed normal-daemon
    ratio of 1.1429 at the coarser resolution, not from the 1.30 it replaces.
    
    Non-vacuity proven in both directions: a CPU-hogging daemon gives ratio 2.00 and
    FAILS the bound; an erroring daemon reports "daemon reported 3 inference errors"
    and FAILS the deterministic counts. Whole file: 49 passed.
    
    Known limitation, measured and recorded rather than claimed away: under host
    saturation a single in-process CPU hog is itself starved, so the ratio stays at
    1.02 and the bound does not fire (quiet 2.00 vs loaded 1.02). The ratio is
    therefore a gross-regression detector, and the deterministic assertions are what
    retain sensitivity under load. DV-032 already assigns the sensitive quantitative
    comparison to the nightly benchmark gate.
    
    Tolerance and assertion intent preserved; no test skipped or xfailed.

## 2. Failure triage (root cause)

All six matrix jobs failed in tests/test_exp002_r1_driver.py:
`test_real_prin_core_pyd_and_generator_pins_match_repository` invoked the
production verifier `_verify_prin_core_extension()`, which requires the
registered Windows E3 binary (9,290,240 B, SHA-256 37392d06...ee99e). Hosted
Ubuntu builds a `*.so` and hosted Windows jobs build a fresh `*.pyd` whose
bytes legitimately differ from the governed host's registered build, so the
exact-binary assertion cannot hold anywhere except the registered E3 host.
The pin itself is intentionally host-registered (DV-047); the defect was the
test demanding it unconditionally on every platform.

## 3. Multi-agent review findings remediated

The Perplexity Deep Research report independently validated the other
reviewers' findings. Eight findings were confirmed against current code and
remediated:

F1  Host-specific live binary test (the hosted failure above).
    Fix: generator-pin assertions run portably; the exact-binary assertion is
    an opt-in test skipped unless explicitly selected on the governed E3
    host. `_verify_prin_core_extension()` is unchanged and remains strict.
F2  `Path.absolute()` preserves `..`: lexical checks could admit traversal
    aliases resolving into immutable predecessor roots.
    Fix: `_resolved_confinement_path` rejects `..` components and resolves
    for comparison; `_reject_predecessor_path`, `_snapshot`,
    `collect_reproduction`, `_reserve`, `check_run_complete` enforce it.
    Unresolved `.absolute()` paths are still used for symlink-ancestor
    detection so symlinks are caught before resolution.
F3  Storage-cap violations were only detected at closure, after COMPLETED
    had been published and manifested.
    Fix: prospective `_storage_check(run, prospective + _FINALIZATION_ALLOWANCE)`
    runs before result publication; any failed run writes a durable
    `abort.json` (manifested, append-only) that `check_run_complete` rejects,
    so an aborted run can never become an admissible completed observation.
F4  Reference arm could import an installed/shadowing `prinet` or fail with
    ModuleNotFoundError; import preceded pin verification.
    Fix: fail-closed bootstrap — reject preloaded `prinet`, verify all
    REFERENCE_PINS pre-import, prepend `REFERENCE/src` to sys.path, require
    `importlib.util.find_spec("prinet")` to resolve to the frozen
    `src/prinet/__init__.py`.
F5  Registered source pins were not uniformly enforced.
    Fix: `_verify_all_pins()` (extension + both PRIN generators + all three
    REFERENCE sources) runs at admission and again before result publication.
F6  Shallow git pathspecs missed nested rogue `.py`/`.pth` files; no
    environment shadowing check existed.
    Fix: recursive `_SHADOW_PATHSPECS` scoped to the governed import surface
    (untracked incl. ignored files) plus `_environment_shadowing()` covering
    site `.pth` path entries and effective `prin`/`prinet` resolution.
F7  `pdf_info_keyset` residuals could be misclassified from digest
    differences alone (identical /Info key sets can serialize differently).
    Fix: preregistration.md §11.1 now requires E4 to inspect actual /Info
    key sets and residual byte structure; digest disagreement alone is
    insufficient.
F8  verification-gate.txt lacked a head-specific full local gate record and
    .gitattributes covered only the e1 evidence root.
    Fix: this bundle was regenerated for the remediation head (local gate
    vs hosted checks distinguished); .gitattributes now covers
    `EVIDENCE/exp002-r1-e*/**`.

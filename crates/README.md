# PRIN Rust workspace crates

| Crate | Responsibility | Phase |
|---|---|---|
| `prin-dynamics` | Oscillator state, models (Kuramoto/Stuart–Landau/Hopf), integrators, PAC, coupling topologies, continuous band networks, temporal propagation | 1–2 |
| `prin-metrics` | Order parameters, coherence, PSD, chimera metrics, sparse variants | 1 |
| `prin-tensor` | Tucker/HOSVD and CP/PARAFAC decomposition | 2 |
| `prin-kernels` | Single-source fused GPU/CPU kernels (CubeCL) + CPU SIMD fallback. Phase 0 mean-field RK4 spike is active (`cpu`/`wgpu`/`cuda` features). WP-017 delivered the backend abstraction, preallocated buffer pools (`MeanFieldRk4Buffers`, `CubeclBufferPool`), cross-backend equivalence harness, and automatic `step_auto` dispatch with graceful CPU fallback. WP-018 added the hierarchical device-side order-parameter reduction (`order_param_block_reduce`/`order_param_device`) and real device-event timing (`TimingMethod`, `StepReport::timing_method`). WP-019 added sparse k-NN coupling (`SparseKnnGraph`, `sparse_knn_derivatives_cpu`, `sparse_knn_coupling_cubecl`) and PAC modulation (`PacParams`, `pac_modulate_cpu`, `pac_modulate_cubecl`) kernels with CSR/index interoperability. WP-020 added the fused three-band discrete-time step (`discrete_step_cpu`, `discrete_step_cubecl`) with reusable hierarchical order-parameter/mean-phase reductions (10-launch fused path). WP-021 delivered dispatch-priority fixes, hardware CUDA kernel-equivalence validation across all four kernel families, and Phase 3 exit gate closure. WP-036 added `src/compat.rs` — CPU reference compatibility functions (`pytorch_*` family, sparse-coupling helpers) exposed as PyO3 bindings for the PRINet 3.0 compatibility surface | 0+3+6 |
| `prin-sim` | OscilloSim engine: CSR sparse, 1M+ oscillators, pruning, sweeps, CPU dispatch, and GPU kernel integration (`GpuSparseKuramoto`, `GpuMeanFieldEngine`, `GpuBandStepper`). WP-036 added `src/compat.rs` — compatibility functions for the PRINet 3.0 surface (sparse-coupling helpers, k-NN neighbors, sweep engine, `phase_to_rate`) exposed as PyO3 bindings | 2+3+6 |
| `prin-train` | Burn-based trainable layers, inhibition/STE, activations, HEP, optimizers, attention, tracking architectures, baselines, ablations, allocation. WP-022 delivered trainable multi-rate bands (`DiscreteDeltaThetaGamma`) and Kuramoto resonance layers (`ResonanceLayer`). WP-023 added feedback inhibition with hard/soft STE (`FeedbackInhibition`), complex/phase activations (`d_silu`, `ComplexTensor`, `HolomorphicActivation`, `phase_activation`, `GatedPhaseActivation`), holomorphic energy functions (`HolomorphicEnergy`), and the ±β HEP trainer (`HolomorphicEp`). WP-024 added oscillator-aware optimizers: `SyncGd` (synchronized gradient descent with sync-barrier penalty), `Rip` (Hebbian coupling-matrix update), `Scalr` (adaptive lr with oscillation-aware decay), and the shared `feedback::OscillatorOptimizer` contract. WP-025 added `validate_shapes` to `ResonanceLayer`/`GatedPhaseActivation` for checkpoint shape validation. WP-026 added `OscillatoryAttention` (phase-coherence-biased multi-head attention), `PhaseTracker` (PRIN's primary contribution — phase-based multi-object tracker), `HybridPRINetV2` (canonical oscillator+attention classifier), the `SlotAttentionModule`/`TemporalSlotAttentionMOT` non-oscillatory comparison baseline, four structural ablation variants, and `AdaptiveOscillatorAllocator`/`DynamicPhaseTracker` for complexity-driven oscillator-count allocation. Exec-WP-026 S1 added `validate_shapes` to all six new types (a real checkpoint-corruption bug found and fixed this session — see `prin-py`'s row) and delivered the PyO3/Python bindings WP-026 S1 had carried forward | 4 |
| `prin-daemon` | Subconscious ONNX controller (WP-028): state/control types (`SubconsciousState`, `ControlSignals`), hand-written ONNX `ModelProto` reader, SHA-256 model validation, VitisAI→DirectML→CPU backend detection and deterministic fallback. WP-029 added the native daemon thread, lifecycle, and lock-free control-signal ring buffer (`ControlSignalBuffer`). WP-030 added `hooks::TrainingHooks` (loss EMA/variance, gradient-norm EMA, step-latency percentiles feeding `SubconsciousState`) and `mot::MotAccumulator` (CLEAR-MOT/IDF1 metrics validated against real `py-motmetrics`, IoU distances, deterministic synthetic sequence generators), backed by a private rectangular Hungarian/Kuhn–Munkres solver (`assignment`) | 5 |
| `prin-py` | PyO3 extension crate (the only crate that links Python). WP-025 added `bindings/train.rs` (PyO3/DLPack `torch.autograd.Function` bridges: `ResonanceLayerBridge`/`GatedPhaseActivationBridge`), `dlpack.rs` helpers (`read_dlpack_f64`/`export_dlpack_f64`), and `python/prin/nn/__init__.py` (`ResonanceLayer`/`GatedPhaseActivation` `torch.nn.Module` wrappers). Exec-WP-026 S1 added `bindings/train_support.rs` (rank-generic DLPack helpers shared by every bridge, including `train.rs`'s own two refactored to use them) and six new bridge modules (`attention`/`phase_tracker`/`hybrid`/`slot_attention`/`ablation`/`allocation`) plus the matching `python/prin/nn/*.py` wrapper modules — see `prin-py/README.md` for the full breakdown, including a real checkpoint-corruption bug (`Module::load_record` silently ignores plain `usize` fields) found and fixed. WP-036 added `bindings/tensor.rs` (PolyadicTensor/CPDecomposition over `prin-tensor`), `bindings/train_layers.rs` (dSiLU/PhaseActivation/HolomorphicActivation/FeedbackInhibition/HolomorphicEnergy/HolomorphicEPTrainer over `prin-train`), `bindings/kernels.rs` (15 `pytorch_*` CPU reference family + sparse-coupling helpers over `prin-kernels`), `bindings/sweep.rs` (sweep_coupling_params/detect_oscillation/phase_to_rate over `prin-sim`; DV-012 closed) | 0+4+6 |

Dependency rule: crates may depend only on crates above them in the layering
`dynamics → metrics/tensor/kernels → sim/train/daemon → py`. `prin-py` is the
sole Python link point. See `DOCS/PRIN_Project_Plan.md` §5.
